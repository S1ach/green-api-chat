# Веб-чат MAX на GREEN-API

## О проекте

React-интерфейс для отправки и получения сообщений в мессенджере MAX через
[GREEN-API](https://green-api.com). Тестовое задание на позицию Frontend React-разработчика.

Пользователь вводит `idInstance` и `apiTokenInstance`, создаёт чат по номеру телефона, пишет
сообщение и видит ответы собеседника. Отправка идёт методом `SendMessage`, приём — по технологии
**HTTP API** (`ReceiveNotification` + `DeleteNotification`, без вебхуков). Бэкенда нет: браузер
обращается к GREEN-API напрямую. Интерфейс окрашен в фирменные цвета
GREEN-API, а компоненты собраны по образцу UI-кита MAX — [max-ui](https://github.com/max-messenger/max-ui).

## Возможности

- Подключение инстанса: `apiUrl`, `idInstance`, `apiTokenInstance` проверяются методом
  `getStateInstance`. Для состояний `notAuthorized`, `pendingPassword`, `starting`, `blocked` и других
  показывается подсказка, что делать.
- Создание чата по номеру телефона. Номер можно вводить в любом виде (`+7 999 123-45-67`,
  `8 (999) 123-45-67`, `79991234567`); `CheckAccount` подтверждает, что он есть в MAX, и отдаёт `chatId`.
- Отправка текстовых сообщений: `Enter` — отправить, `Shift+Enter` — новая строка. Сообщение сразу
  появляется в ленте со статусом «отправляется», затем «отправлено», «доставлено», «прочитано».
  Если отправка не удалась, сообщение остаётся в ленте с причиной и кнопками «Повторить» и «Удалить».
- Скрепка у поля ввода — меню вложений, как в мессенджере:
  - **Файл** — любой файл с диска до 100 МБ (`SendFileByUpload`); текст из поля ввода уходит подписью;
  - **Контакт** — выбирается из контактов аккаунта MAX (`GetContacts` → `SendContact`), есть поиск;
  - **Геопозиция** — координаты вводятся вручную или берутся у браузера (`SendLocation`); в ленте
    геопозиция открывается на карте.
- Получение новых сообщений без перезагрузки страницы — из очереди уведомлений. Показываются
  и сообщения, отправленные с телефона или из другого клиента MAX.
- Вложения (фото, видео, аудио, файлы, геопозиция, контакт, опрос) не теряются: в ленте видно,
  что пришло, подпись и ссылка на файл; у геопозиции — координаты, у контакта — имя.
- Список чатов и история переписки загружаются с сервера, поэтому видны и после перезагрузки
  страницы, и на другом компьютере. Более ранние сообщения подгружаются по кнопке.
- Диалог: входящие слева, исходящие справа, серии сообщений одного автора, разделители дней, время.
  Лента не мешает читать историю: новые входящие считаются на кнопке «вниз».
- Аватары собеседников. Ссылка на аватар хранится вместе с чатом и запрашивается раз в неделю,
  а не при каждой загрузке страницы.
- Поиск по списку чатов: по имени собеседника и по номеру телефона в любом формате ввода.
- «Избранное» (чат с самим собой) отмечено закладкой вместо аватара. Стрелка в шапке закрывает
  открытый чат.
- Лимиты GREEN-API соблюдаются автоматически; при ответе 429 запрос повторяется после паузы.
- Если настройки инстанса мешают приёму сообщений, приложение говорит об этом и предлагает включить
  нужные уведомления одной кнопкой.
- Светлая и тёмная тема по системной настройке; на экране уже 760 px видно либо список, либо переписку.

## Использование

1. Создайте инстанс для мессенджера **MAX** в [console.green-api.com](https://console.green-api.com)
   и авторизуйте его по QR-коду (в MAX: Профиль → Устройства → «Войти по QR-коду»; пароль на вход
   в MAX нужно отключить, иначе QR-код не сработает).
2. Скопируйте `idInstance`.
3. Скопируйте `apiTokenInstance`. Если в консоли указан свой `apiUrl`, скопируйте и его.
   Поле `mediaUrl` (хост для отправки файлов) необязательно: без него файлы уходят через `apiUrl`.
4. Запустите приложение: `npm run dev`.
5. Введите учётные данные и нажмите «Войти».
6. Нажмите «+» → «Новый чат» и введите номер получателя.
7. Нажмите «Создать чат».
8. Напишите сообщение и нажмите `Enter`. Ответ собеседника появится слева без перезагрузки страницы.

### Настройка инстанса для приёма по HTTP API

Чтобы уведомления попадали в очередь, а не уходили на вебхук, в настройках инстанса должно быть:

- **webhookUrl** — пусто;
- **incomingWebhook** — `yes` (уведомления о входящих сообщениях).

Приложение проверяет это методом `GetSettings`. Если `incomingWebhook` выключен, в плашке над чатом
есть кнопка «Включить»: методом `SetSettings` она включает уведомления о входящих (`incomingWebhook`),
о сообщениях с телефона (`outgoingMessageWebhook`) и о статусах доставки (`outgoingWebhook`).
После этого инстанс перезапускается, настройки применяются до 5 минут. Заданный `webhookUrl`
приложение не трогает — его нужно очистить в консоли самостоятельно.

Проект разложен по слоям [Feature-Sliced Design](https://feature-sliced.design). Зависимости идут
только сверху вниз, слайсы подключаются через публичный API (`index.ts`); оба правила проверяет
ESLint (`no-restricted-imports` в [eslint.config.js](eslint.config.js)).

```text
│   └── styles/               дизайн-токены MAX, reset
├── pages/
│   ├── login/                экран подключения инстанса
│   └── chat/                 сайдбар + диалог, плашки о состоянии связи
├── widgets/
│   ├── sidebar/              Sidebar, SidebarMenu, ChatList, ChatListItem
│   └── chat/                 Chat, ChatHeader, MessageList, прокрутка и разметка ленты
├── features/
│   ├── configure-instance/   форма учётных данных, подключение и выход
│   ├── create-chat/          форма номера, CheckAccount
│   ├── send-message/         поле ввода, отправка со статусами и повтором
│   ├── receive-message/      цикл опроса очереди, проверка и исправление настроек инстанса
│   ├── sync-chats/           GetChats и сверка сообщений по журналам
│   ├── load-history/         GetChatHistory для открытого чата, подгрузка ранних сообщений
│   └── search-chats/         строка поиска и фильтр списка чатов
├── entities/
│   ├── session/              учётные данные (slice)
│   ├── chat/                 чаты и сообщения (slice), аватар
│   └── message/              модель Message, разбор уведомлений, истории и журналов, MessageBubble
└── shared/
    ├── api/                  RTK Query: endpoints GREEN-API, baseQuery, ограничитель частоты, ошибки
    ├── config/               константы
    ├── lib/                  typed hooks, нормализация номера, хранилище, утилиты
    ├── styles/               SCSS-миксины: типографика MAX
    └── ui/                   Button, IconButton, TextField, Avatar, Menu, Modal, Alert, Loader…
```

**Состояние.** В Redux лежит только то, что нужно нескольким частям приложения: учётные данные,
чаты, сообщения и открытый чат. Текст в поле ввода, значения форм, поисковый запрос и открытость
меню — локальное состояние компонентов. Серверное состояние (настройки инстанса, история, контакты)
живёт в кэше RTK Query.

**API.** Все обращения к GREEN-API описаны в [src/shared/api/greenApi.ts](src/shared/api/greenApi.ts)
через `createApi` и `fetchBaseQuery`. Учётные данные — часть URL, поэтому адрес собирает `baseQuery`;
компоненты про токен не знают. Тело ответа проверяется Zod-схемой до того, как попадёт в приложение.

## Откуда берутся сообщения

Сообщения приходят из четырёх источников и сводятся в один список в slice чатов. Дубли отсекаются
по `idMessage`, поэтому одно сообщение из двух источников показывается один раз.

| Источник                                        | Когда                       | Что даёт                                 |
| ----------------------------------------------- | --------------------------- | ---------------------------------------- |
| `ReceiveNotification`                           | постоянно, long polling     | новые сообщения и статусы без задержки   |
| `LastIncomingMessages` / `LastOutgoingMessages` | при входе и раз в 30 секунд | превью всех чатов; страховка для очереди |
| `GetChatHistory`                                | при открытии чата           | история чата, по 100 сообщений           |
| `SendMessage` и методы отправки вложений        | при отправке                | собственное сообщение и его `idMessage`  |

### Очередь уведомлений

```text
receiveNotification?receiveTimeout=5
        ↓
очередь пуста (null)? → следующий receiveNotification
        ↓
parseNotification(body) → сообщение, статус или null
        ↓
messageReceived / messageStatusChanged → нужный чат в store
        ↓
deleteNotification/{receiptId}
        ↓
следующий receiveNotification
```

Реализация — [useNotificationPolling](src/features/receive-message/model/useNotificationPolling.ts):

- цикл один и строго последовательный: следующий запрос уходит только после обработки предыдущего;
- цикл останавливается при размонтировании страницы, выходе и смене учётных данных; запрос,
  который в этот момент в полёте, отменяется;
- каждое уведомление удаляется, даже ненужное приложению, — иначе очередь встанет;
- принимаются `incomingMessageReceived`, `outgoingMessageReceived`, `outgoingAPIMessageReceived`
  и `outgoingMessageStatus`; реакции, правки и удаления в ленту не попадают;
- при ошибках — пауза от 1 до 30 секунд с экспоненциальным ростом и плашка в интерфейсе.

### Сверка по журналам

Очередь уведомлений у инстанса одна, и сообщение в неё может не попасть: выключена настройка,
уведомление забрал другой клиент, приложение было закрыто дольше суток. Поэтому раз в 30 секунд
приложение перечитывает журналы за последние 10 минут
([useChatSync](src/features/sync-chats/model/useChatSync.ts)). Сверка без новых сообщений
не меняет состояние и ничего не перерисовывает; в скрытой вкладке она не идёт.

## Лимиты GREEN-API и ошибка 429

GREEN-API ограничивает частоту запросов **на каждый метод** и отвечает 429 при превышении. У методов,
которые использует приложение: `GetChatHistory`, `GetChats`, `GetSettings`, `SetSettings`, журналы,
`GetContacts`, `GetAccountSettings` и `getStateInstance` — 1 запрос в секунду; `CheckAccount`,
`GetAvatar` и `GetContactInfo` — 10; `SendMessage`, `SendFileByUpload`, `SendContact` и `SendLocation` — 50.

Как приложение с этим работает ([baseQuery](src/shared/api/baseQuery.ts),
[rateLimiter](src/shared/api/rateLimiter.ts)):

- запросы одного метода выстраиваются в очередь с интервалом не меньше лимита, из какой бы части
  приложения они ни пришли;
- одинаковые запросы объединяются в один;
- при ответе 429 запрос повторяется: пауза берётся из заголовка `Retry-After`, а если его нет —
  растёт экспоненциально (1, 2, 4 секунды); повторов не больше трёх;
- пока запрос ждёт, пользователь видит «Слишком много запросов. Повторная попытка через N с.»,
  а не ошибку;
- истории открытого чата запрашивается 100 сообщений, и повторно она не загружается, если получена
  меньше минуты назад;
- превью чатов берутся из журналов — двумя запросами на аккаунт, а не запросом на каждый чат.

### Месячные квоты бесплатного тарифа

На тарифе MAX Developer у нескольких методов есть квота на месяц: у `GetAvatar`, `GetContactInfo`
и `CheckAccount` — по 100 запросов; сверх неё сервер отвечает 466 до первого числа следующего
месяца. Аватары расходовали квоту быстрее всего — запрос на каждый чат при каждой загрузке страницы,
— поэтому ([loadChatAvatar](src/entities/chat/model/loadChatAvatar.ts)):

- ссылка на аватар хранится в самом чате и вместе с ним в `localStorage`; у API она запрашивается,
  только когда её ещё нет или ей больше недели;
- «аватара нет» тоже запоминается — о таких чатах приложение не спрашивает заново;
- если сохранённая ссылка перестала открываться, новая запрашивается один раз сразу;
- когда `GetAvatar` недоступен, для личного чата и бота ссылка берётся из `GetContactInfo`;
- при исчерпанной квоте следующая попытка откладывается до начала месяца, при прочих сбоях — на час.

## Дизайн

Все цвета, отступы, радиусы и размеры шрифта заданы токенами в
[variables.scss](src/app/styles/variables.scss); в стилях компонентов цветов нет.

**Цвета — фирменная палитра GREEN-API.** Значения взяты из CSS-переменных сайта green-api.com:

| Где используется                                | Светлая тема | Тёмная тема |
| ----------------------------------------------- | ------------ | ----------- |
| Кнопки, счётчики, рамка фокуса (`--main-color`) | `#3b9702`    | `#3b9702`   |
| Наведение на кнопку (`--main-hover-color`)      | `#2d7301`    | `#2d7301`   |
| Исходящие сообщения, выбранный чат              | `#e6ff9d`    | `#2d7301`   |
| Ссылки, текстовые кнопки, иконки                | `#2d7301`    | `#3bd671`   |
| Фон страницы                                    | `#f5f5f5`    | `#111111`   |
| Панели                                          | `#ffffff`    | `#1a1a1a`   |
| Фон переписки (`--status-up-color`)             | `#d5e9c9`    | `#111111`   |
| Ошибки (`--status-down-color`)                  | `#df484a`    | `#df484a`   |

Для текста на светлом фоне используется тёмный вариант зелёного (`#2d7301`): основной `#3b9702`
на белом читается хуже. Тёмная тема включается по системной настройке.

Фон переписки — белый узор [chat-background.svg](src/shared/assets/chat-background.svg) поверх
цветной подложки. Узор лежит отдельным слоем, поэтому его заметность задаёт тема: в светлой он виден
полностью, в тёмной почти растворён. Всё, что лежит прямо на фоне (дата, пустое состояние, ошибка
отправки), имеет собственную подложку.

**Форма компонентов — по [max-ui](https://github.com/max-messenger/max-ui).** Оттуда взяты имена
токенов, шкала отступов, радиусы, типографика и сами компоненты: кнопки трёх размеров с состояниями,
поля с заливкой, ячейка списка, счётчик, аватар с градиентом, спиннер. Готовых компонентов чата
в max-ui нет (кит рассчитан на мини-приложения), поэтому пузыри сообщений, лента и поле ввода
собраны из тех же токенов.

## Тесты

```bash
npm run test
```

- **API-слой** — URL и тела запросов, проверка формата ответов, тексты ошибок; повтор после 429,
  `Retry-After`, предел числа повторов, интервал между запросами одного метода.
- **Приём сообщений** — один цикл даже в StrictMode, удаление каждого уведомления, отсутствие дублей,
  исходящие с телефона, статусы, вложения, остановка при размонтировании.
- **Сверка** — загрузка на «новом компьютере» без `localStorage`, появление сообщения, которого
  не было в очереди, отсутствие изменений при повторной сверке.
- **Состояние** — сопоставление сообщения с чатом, непрочитанные, слияние без потери старых
  сообщений, замена временного идентификатора после отправки, повышение статуса.
- **Разбор данных** — уведомления, история и журналы, порядок сообщений внутри одной секунды,
  нормализация номера.
- **UI через поведение пользователя** — сообщение и его статусы, запрет отправки пустого сообщения,
  защита от двойной отправки, `Enter` / `Shift+Enter`, повтор отправки, состояния ленты, прокрутка,
  подгрузка истории, быстрое переключение и закрытие чата, поиск, формы.
- **Вложения** — меню скрепки, отправка файла с подписью, проверка размера, повтор после ошибки;
  выбор контакта (загрузка, поиск, ошибка, пустой список); проверка и отправка координат.
- **Сценарий из ТЗ целиком** — подключение → новый чат → отправка → получение ответа → выход.

В тестах GREEN-API подменяется на уровне `fetch`; в самом приложении моков и имитации сообщений нет.

## Security

- Учётные данные **не хранятся в репозитории**: их вводит пользователь, в коде, тестах и README
  настоящих значений нет. Файлы `.env*` добавлены в `.gitignore`.
- Введённые данные сохраняются только в `localStorage` браузера и уходят исключительно в запросы
  к указанным `apiUrl` и `mediaUrl`. Кнопка «Выйти» удаляет их.
- Местоположение запрашивается у браузера только по кнопке «Моё местоположение» и уходит
  только в отправляемое сообщение. Ссылка на карту в ленте ведёт на Яндекс Карты.
- `apiTokenInstance` не попадает в логи: URL запросов и тексты сообщений не логируются.
- Текст сообщений выводится как текст, а не как разметка; ссылками становятся только адреса `http(s)`.
- Бэкенда нет, поэтому токен доступен в браузере пользователя. Для продакшена его стоит спрятать
  за серверным прокси.

## Ограничения

- Вложения показываются названием и ссылкой, без предпросмотра. Отправляется один файл за раз;
  фото это, видео или документ, MAX определяет сам по расширению файла.
- Поделиться можно только контактом из списка контактов аккаунта MAX — это ограничение `SendContact`.
  Список GREEN-API обновляет с задержкой до 5 минут.
- Неотправленный файл не переживает перезагрузку страницы: повторить отправку такого сообщения
  нельзя, файл нужно выбрать заново.
- Где у геопозиции и контакта лежат данные в `GetChatHistory`, документация не описывает. Отправленные
  из приложения сообщения помнят координаты и имя сами; у пришедших из истории может остаться
  только название вложения.
- Приложение зависит от GREEN-API: его доступности, тарифа и лимитов частоты запросов.
- На бесплатном тарифе аватары пропадают, когда исчерпана месячная квота `GetAvatar` и
  `GetContactInfo`: уже сохранённые остаются, новые появятся после первого числа.
- Сменённый собеседником аватар обновится в приложении в течение недели.
- История ограничена самим MAX: не больше 5000 сообщений и не глубже 3 месяцев. У `GetChatHistory`
  нет смещения, поэтому более ранние сообщения получают, запрашивая больше.
- Уведомление в очереди получает только один клиент. Если очередь читает ещё кто-то, новое сообщение
  появится не сразу, а при следующей сверке по журналам — в пределах 30 секунд.
- Статусы «доставлено» и «прочитано» обновляются сразу, только если у инстанса включён
  `outgoingWebhook`; иначе — при загрузке истории.
- Реакции, правки и удаления сообщений не отображаются.
- Поиск работает по списку чатов (имя и номер); по тексту сообщений он не ищет.
- Номера распознаются для России и Казахстана (`7…`) и Беларуси (`375…`).

## Деплой

- **Vercel** — в репозитории есть [vercel.json](vercel.json): команда сборки `npm run build`, каталог `dist`.
- **GitHub Pages** — workflow [.github/workflows/deploy.yml](.github/workflows/deploy.yml) при пуше
  в `master` запускает линт, проверку форматирования и типов, тесты и сборку, затем публикует `dist`.
  В настройках репозитория нужно включить **Settings → Pages → Source: GitHub Actions**.

GREEN-API разрешает запросы из браузера (CORS), прокси не нужен. Если запросы блокирует сеть или
расширение, для разработки есть запасной вариант: `VITE_USE_PROXY=1 npm run dev` и `apiUrl = /green-api`
в форме входа (см. [vite.config.ts](vite.config.ts)).
